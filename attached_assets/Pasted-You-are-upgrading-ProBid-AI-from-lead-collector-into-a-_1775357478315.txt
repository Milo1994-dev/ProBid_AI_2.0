B) LEAD SCORING
Build a scoring engine that updates score automatically.
Suggested scoring:
+20 if phone exists
+15 if email exists
+10 if website exists
+15 if trade matches core ICP (masonry, roofing, concrete, remodeling, general contractor)
+10 if city/state is in target service regions
+20 if email opened
+25 if clicked
+40 if replied
-50 if unsubscribed / opt-out / invalid
-20 if bounced
-15 if already contacted too many times
Cap score between 0 and 100

Priority buckets:
- hot: 70+
- warm: 40-69
- cold: 0-39

C) OUTREACH SEQUENCES
Build 3 sequences:
1. email_first
2. sms_first
3. hybrid

Default sequence = hybrid when both email and phone exist.
If only email exists -> email_first
If only phone exists -> sms_first

SEQUENCE RULES

HYBRID:
Day 0: Intro email
Day 1: SMS nudge
Day 3: Follow-up email
Day 5: Final SMS
Day 8: Breakup email
Then mark as no_response if no opens/clicks/replies

EMAIL_FIRST:
Day 0: Intro email
Day 2: Follow-up email
Day 5: Case study/value email
Day 8: Breakup email

SMS_FIRST:
Day 0: Intro SMS
Day 2: Follow-up SMS
Day 5: Last chance SMS

Stop all future steps immediately if:
- reply detected
- subscribed
- opted out
- hard bounce
- doNotContact = true

E) REPLY HANDLING
Build reply detection flow.

EMAIL:
- Use existing email provider webhook/events if available
- Capture opens, clicks, bounces, replies if provider supports it
- Update stage automatically:
  opened -> clicked -> replied
- When reply detected:
  - cancel queued follow-ups
  - set stage = replied
  - create admin notification
  - add note/log entry

SMS:
- Add Twilio inbound webhook route
- Parse inbound STOP / STOPALL / UNSUBSCRIBE / CANCEL / END / QUIT
- If stop keyword received:
  - smsOptOut = true
  - doNotContact = true if only SMS is available
  - cancel future SMS
- For normal replies:
  - stage = replied
  - lastReplyAt = now
  - cancel pending steps
  - admin notification
